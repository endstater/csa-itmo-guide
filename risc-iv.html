risc-iv

RISC, регистр-регистр (load-store) архитектура

1. Что это

RISC (Reduced Instruction Set Computer) — процессор с простыми однотипными инструкциями: единый формат, доступ к памяти только через load/store, все операции — над регистрами. Сложность перенесена в компилятор, а не в железо.

Регистр-регистр (load-store) — стиль системы команд, при котором арифметика работает только с регистрами, а память трогают отдельные инструкции загрузки и сохранения. Это и есть ключевое отличие от acc32 и m68k, где арифметика может обращаться к памяти.

Термины:

  • Регистр — ячейка внутри процессора, доступ к ней не идёт по шине памяти. Регистровый файл — набор таких ячеек.
  • Load-store архитектура — память читается только load, пишется только store, между ними данные живут в регистрах.
  • Конвейер — DataPath, разрезанный регистрами на стадии; RISC строился под конвейер (лекция 9).

Почему RISC появился (лекция 9): замеры показали, что сложные инструкции и режимы адресации CISC компиляторы почти не используют; сами компиляторы умеют собирать сложное из простого; с VLSI процессор помещается на один кристалл, и место под микрокод/декодер выгоднее отдать регистрам и кешу. Первые проекты — IBM 801 (1975), Berkeley RISC и Stanford MIPS (1981).

В таблице «ISA и конвейер» (лекция 10) risc-iv — единственный из учебных ISA, который «конвейеризуется просто»: одна длина инструкции, load/store, много регистров.

2. Система команд

Полный перечень инструкций risc-iv-32 — в документации wrench. Ниже — то, что встречается в лекциях, в вопросах к защите и в реальной работе над лабой.

Регистры

32 регистра, из них:

  • zero — константа 0, запись игнорируется;
  • ra — адрес возврата из процедуры (caller-saved);
  • sp — указатель стека (callee-saved);
  • gp, tp — глобальный и thread-указатели (callee-saved);
  • a0–a7 — аргументы и возвращаемые значения (caller-saved);
  • t0–t6 — временные (caller-saved);
  • s0/fp, s1–s11 — сохранённые (callee-saved).

Caller-saved — вызываемая функция может испортить, не восстанавливая. Callee-saved — вызываемая обязана сохранить и восстановить, если меняла.

Режимы адресации

Из таблицы адресации лекции 8 для risc-iv указаны:

РежимПример
регистроваяadd a0, a1, a2
со смещением (базовая)lw a0, 8(sp) — по адресу база + смещение

В лекции отмечено: по замерам Hennessy и Patterson на VAX смещение, непосредственная и косвенная регистровая дают 75–99% использований — поэтому в RISC-V для памяти оставили один режим «база + смещение». Вопрос к защите «что означает 0(t1)» — ровно про эту форму: адрес = содержимое регистра t1 плюс смещение 0.

%hi и %lo

Адрес или 32-битную константу нельзя загрузить одной инструкцией — поле слишком узкое. Собирается из двух:

lui  a0, %hi(address)     ; старшие 20 бит
addi a0, a0, %lo(address) ; младшие 12 бит (signed)

%hi(sym) = ((sym + 0x800) >> 12) & 0xFFFFF — округление вверх на 0x800 компенсирует знаковое расширение %lo. %lo(sym) = signext(sym[11:0]).

3. Требования к лабе

Из lab3-task.md — специфика именно для risc-iv-32:

  • использование вложенных процедур (одна процедура вызывает другую) — чтобы продемонстрировать работу со стеком;
  • где применимо — рекомендуется рекурсивное решение задачи;
  • схема именования меток, помогающая видеть структуру кода.

Общие требования (для всех ISA):

  • ввод через 0x80, вывод через 0x84;
  • 32-битное слово по умолчанию;
  • ввод вне области определения — -1; переполнение — байты 0xCC;
  • .org 0x88 — данные сразу за MMIO-портами, иначе зря сжигается 120 байт;
  • код отформатирован, журнал не обрезан; сдача — не чаще раза в 24 часа.

Почему «вложенные процедуры» — это требование про стек: при вызове одной процедуры из другой адрес возврата (ra) нужно сохранить в кадр стека, иначе он затрётся. В лекции 9 это показано на примере: у листовой функции square кадра нет, а у sum_of_squares, которая дважды её вызывает, — есть.

4. Пример кода

Из лекции 9 — sum_of_squares с кадром стека (главный пример работы со стеком на risc-iv):

square:                       ; a0 = a0 * a0
    mul   a0, a0, a0
    jalr  zero, ra, 0

sum_of_squares:               ; a0 = a0*a0 + a1*a1
    addi  sp, sp, -12         ; кадр
    sw    ra, 8(sp)
    sw    s0, 4(sp)
    sw    s1, 0(sp)
    mv    s0, a1              ; b переживёт вызов
    jal   ra, square          ; a0 = a*a
    mv    s1, a0
    mv    a0, s0
    jal   ra, square          ; a0 = b*b
    add   a0, a0, s1
    lw    ra, 8(sp)           ; снять кадр
    lw    s0, 4(sp)
    lw    s1, 0(sp)
    addi  sp, sp, 12
    jalr  zero, ra, 0

Что здесь видно про архитектуру:

  • Кадр стека — sp уменьшается на 12, туда сохраняются ra, s0, s1. После вызовов стек «снимается» обратными lw и addi sp, sp, 12.
  • ra обязательно сохранять во вложенных вызовах: второй jal перезапишет адрес возврата, если его не положить в память.
  • s0 хранит b, потому что a1 затирается вызовом square — значения переживают вызов только в сохранённых регистрах или в памяти.
  • Доступ к памяти — только lw/sw; mul и add работают исключительно с регистрами.

Чтение MMIO и запись результата — идиома lui %hi + addi %lo + lw/sw:

    .data
    .org 0x88
input_addr:     .word 0x80
output_addr:    .word 0x84
    .text
_start:
    lui  t0, %hi(input_addr)
    addi t0, t0, %lo(input_addr)
    lw   t0, 0(t0)            ; t0 <- *input_addr = 0x80
    lw   a0, 0(t0)            ; a0 <- *0x80 (вход)
    jal  ra, sum_of_digits    ; вызов процедуры
    lui  t0, %hi(output_addr)
    addi t0, t0, %lo(output_addr)
    lw   t0, 0(t0)            ; t0 <- *output_addr = 0x84
    sw   a0, 0(t0)            ; *0x84 <- результат
    halt

Сравнение из лекции 9: на стековой машине этот алгоритм — 5 «слов», на risc-iv — 15 инструкций, из них 8 на кадр. Вывод лекции: в Forth пишут много мелких слов, а в регистровых архитектурах компилятор встраивает (inline) мелкие функции.

5. Грабли (из личного опыта)

  1. sp по умолчанию 0. В _start надо явно загрузить вершину стека (например, из ячейки stack_top), иначе addi sp, sp, -N уйдёт в отрицательные адреса и упадёт с memory access error.
  2. addi — 12-битный signed. Диапазон -2048..2047. Вершина стека 0xFF0 (4080) не влезает, 0x7F0 (2032) — влезает. Если нужно больше — через lui+addi.
  3. lui не принимает отрицательные. imm ∈ [0, 1048575]. Для маленьких констант удобнее addi rd, zero, imm.
  4. li не существует. Только lui+addi. Для маленьких — addi rd, zero, imm.
  5. div и rem — signed, как в C. Quotient toward zero, remainder со знаком делимого: -456 % 10 = -6, -456 / 10 = -45. Это не Python-семантика (там floor division и remainder со знаком делителя). Значит, знак остатка снимать вручную (sub zero, t).
  6. divu и remu не существуют. Только signed.
  7. Флага переполнения нет. Перенос и знаковое переполнение проверяются программно (сравнение знаков операндов и результата).
  8. abs(INT32_MIN) переполняется. Нельзя бездумно брать модуль минимального 32-битного числа. Обход: применять abs только к остатку rem ∈ [-9, 9], а не ко входу.
  9. Встроенные тесты могут дать 512 байт. Свой memory_size: 0x1000 их не исправит — надо влезать в их лимит. Проверка: wrench файл.asm --isa risc-iv-32 без -c.
  10. .org 0x88 экономит 120 байт. При дефолтных 512 это часто решает «влезает / не влезает».
