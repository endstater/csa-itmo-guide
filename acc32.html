Аккумуляторная архитектура

1. Что это

Аккумулятор — единственный регистр, с которым работает арифметика. В аккумуляторной архитектуре почти каждая операция имеет вид Acc = Acc op mem[X]: один операнд всегда в аккумуляторе, второй берётся из памяти. Результат возвращается в аккумулятор.

Это исторически первый массовый стиль: в 1940–50-х регистры были дороги (лампы), поэтому процессор делали с минимумом железа — одним регистром. В лекции курс начинает с аккумулятора и через CISC идёт к RISC.

По классификации стилей систем команд (лекция 8) аккумуляторная архитектура занимает середину: плотность кода средняя (операнды-регистры не кодируются, но и стековой компактности нет), доступ к памяти — каждая команда. Примеры из лекции: acc32, 6502.

Что важно понимать: в acc32 нет регистров общего назначения и нет «регистрового файла». Всё, что не в аккумуляторе, лежит в памяти, а обращение к памяти — это отдельный такт (или несколько).

Одна «сложная» команда на аккумуляторе

Лекция 8 показывает, как CISC-команда раскладывается на acc-микроархитектуре:

add #01 <- 34 + #03
; [ <opcode>, 34, 03, 01 ] 5 тактов

Acc <-   34    ; [ <opcode>, 34 ] 2t
Acc <-+ #03    ; [ <opcode>, 03 ] 3t
#01 <-  Acc    ; [ <opcode>, 01 ] 3t

Вывод лекции: сложные инструкции эффективнее по памяти и времени, но это уже CISC-инструкция на аккумуляторной микроархитектуре. Для acc32 в лабе такие команды не нужны — там пишут цепочками простых.

3. Требования к лабе

Специфичных требований именно для acc32 в lab3-task.md нет — только общие для всех ISA:

  • ввод — через ячейку памяти 0x80; вывод — через 0x84;
  • значение и результат по умолчанию — 32-битное машинное слово;
  • ввод вне области определения — вернуть -1;
  • результат не помещается в машинное слово — вернуть слово, заполненное байтами 0xCC;
  • код отформатирован (вручную или wrench-fmt), журнал работы не обрезан;
  • сдавать одно задание чаще раза в 24 часа нельзя;
  • при использовании процедур — договориться о схеме именования меток.

Что это значит на практике для acc32: раз нет регистров, любая промежуточная величина — это ячейка памяти. Отсюда характерный стиль кода: много load/store вокруг каждой арифметической операции и отдельные ячейки-константы даже для 1 и 4.

4. Пример кода

Фрагмент рабочей реализации strstr_cstr на acc32 (файл lab3-1.asm) — цикл чтения строки из порта ввода до '\n':

_start:
    load_imm    buf         ; Acc <- адрес буфера (литерал, не содержимое)
    store       ptr         ; ptr <- buf: курсор записи в начало

read_loop:
    load        input_addr  ; Acc <- адрес порта ввода (0x80)
    load_acc                ; Acc <- mem[0x80]: следующий символ;
                            ; чтение потребляет символ (MMIO)
    and         const_ff    ; оставить младший байт (код символа)
    store       in_char     ; сохранить символ: Acc сейчас затрётся

    load        in_char
    sub         const_nl    ; сравнение — через вычитание
    beqz        find_bar_start ; Zero -> '\n': строка прочитана

    load        in_char
    store_ind   ptr         ; mem[ptr] <- символ
    load        ptr
    add         const_4     ; ptr += 4: следующий слот (память словная)
    store       ptr
    load        total
    add         const_1     ; total += 1
    store       total
    ...
    jmp         read_loop

Что здесь видно про архитектуру:

  • Чтение из 0x80 — это load input_addr + load_acc: сначала в Acc кладётся адрес порта, потом читается память по этому адресу. Прямого «прочитать по адресу X» нет, есть косвенное чтение через Acc.
  • Сравнение — это вычитание с проверкой результата (sub + beqz). Отдельной команды сравнения в примере нет.
  • Константы лежат в памяти (const_1, const_4, const_nl): у арифметики нет непосредственного операнда, даже +1 — это ячейка.
  • Запись в 0x84 — через store_ind output_addr, по той же схеме «адрес в ячейке».
