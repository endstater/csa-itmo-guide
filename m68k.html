m68k

CISC, регистр-память (register-to-memory) архитектура

1. Что это

m68k (Motorola 68000) — представитель CISC и стиля регистр-память: часть инструкций может обращаться к памяти напрямую, арифметика умеет работать с операндом из памяти, а не только из регистра.

Термины:

  • CISC (Complex Instruction Set Computer) — одна инструкция может выполнять несколько операций (чтение из памяти, вычисление, запись) и иметь сложные режимы адресации; сложность — в процессоре.
  • Режим адресации — способ, которым инструкция указывает, где взять операнд: в регистре, в памяти по адресу, по адресу из регистра и т.п.
  • Регистр-память — стиль, где операнд может быть в памяти; в отличие от load-store (risc-iv), где память трогают только load/store.

Почему CISC появился (лекция 8): в 1960–70-х память была дорогой и медленной, компиляторы слабыми, писали на ассемблере. Сложные команды давали плотный код и меньше обращений к памяти. Проблемы CISC: сложный Control Unit (разная длина и длительность команд), компиляторы используют малую часть команд, сложная команда иногда медленнее цепочки простых.

В таблице стилей лекции 8 у регистр-памяти высокая плотность кода, доступ к памяти — у части команд. Примеры: m68k, x86. В таблице «ISA и конвейер» (лекция 10) CISC конвейеризуется сложно: разная длина, память в арифметике.

Лекция отдельно отмечает автоинкремент/автодекремент как важную особенность: размер операции задаёт шаг указателя (для .l — 4 байта). Это один из типовых вопросов к защите («как работают постинкремент и предекремент, почему важен размер операции»).

CISC-команда movem

Пример из лекции 8 — одна команда сохраняет на стек целую пачку регистров:

movem.l D0-D7/A0-6,-(SP)

Смысл по лекции: список регистров кодируется 16-битной маской, сохранение идёт в обратном порядке; восстановление — movem.l (SP)+,D0-D7/A0-A6. Типичное применение — пролог и эпилог функции, обработчик прерывания. Это и есть «одна инструкция — несколько операций»: на risc-iv то же самое делается серией sw.

3. Требования к лабе

Из lab3-task.md — специфика именно для m68k:

  • использовать различные режимы инструкций и способы адресации;
  • использовать вложенные процедуры и стек;
  • схема именования меток, помогающая видеть структуру кода.

Общие требования (для всех ISA):

  • ввод через 0x80, вывод через 0x84; 32-битное слово по умолчанию;
  • ввод вне области определения — -1; переполнение слова — байты 0xCC;
  • код отформатирован, журнал не обрезан; сдача — не чаще раза в 24 часа.

На практике «разные режимы адресации» означают, что в одной работе нужно показать не только move.l (A0), D0, но и, например, автоинкремент/автодекремент или индексную адресацию — иначе требование не выполнено.

4. Пример кода

Из лекции 8 — программа на ассемблере m68k (симулятор wrench). Считает факториал числа, прочитанного из порта ввода, и пишет результат в порт вывода:

_start:         movea.l 0x80, A0      ; A0 <- 0x80 (адрес ввода)
                movea.l 0x84, A1      ; A1 <- 0x84 (адрес вывода)
                move.l  (A0), D0      ; D0 <- [A0] (n)
                move.l  D0, D1        ; D1 <- D0
loop:           sub.l   1, D1         ; D1 <- D1 - 1
                beq     end           ; если D1 = 0, перейти на end
                mul.l   D1, D0        ; D0 <- D0 * D1
                jmp     loop          ; перейти на loop
end:            move.l  D0, (A1)      ; [A1] <- D0
                halt                  ; остановить выполнение

Что видно про архитектуру:

  • Два файла регистров: A0, A1 — адресные (в них адреса), D0, D1 — данные. Отсюда отдельная инструкция movea.l для адресов.
  • Память в арифметике: move.l (A0), D0 читает память по адресу из A0 — это косвенная регистровая адресация.
  • Непосредственное значение в команде: sub.l 1, D1 — в диалекте wrench непосредственное значение пишется без #.
  • Ввод-вывод — через адреса 0x80/0x84, как обычная память (MMIO).

Замечание из лекции: регистры изначально в «случайном» состоянии, а трасса выполнения (очерёдность смены состояний) показывает, как меняются A0, A1, D0, D1 на каждом шаге. Вопрос к защите про link/unlk и кадр стека в лекциях подробно не разобран — это в документации wrench.
