f32a

Стековая архитектура

1. Что это

Стековая машина — процессор, у которого операнды инструкций неявные: они берутся с вершины стека, результат кладётся туда же, а в инструкции кодируется только операция. Нет полей регистров — поэтому код получается очень компактным.

Ключевые термины:

  • Стек — структура «последним пришёл — первым вышел» (LIFO). push кладёт значение на вершину, pop снимает.
  • Операнд — то, над чем выполняется операция. У стековой машины операнды — это верхние ячейки стека.
  • Стек данных и стек возвратов — в f32a их может быть один или два (по варианту). На стеке данных лежат значения, на стеке возвратов — адреса возврата из процедур.

По классификации лекции 8 стековая архитектура — самая высокая плотность кода: операция занимает байт, полей регистров нет. Доступ к памяти — только через специальные команды @ (чтение) и ! (запись). Примеры: f32a, JVM, WebAssembly.

Историческая справка из лекции 9: прообраз f32a — процессор F18A (Forth-процессор), на его основе сделаны матрицы GreenArrays GA144. Стековые машины применяют во встраиваемых и космических системах (Harris RTX 2010) и в виртуальных машинах (JVM, .NET CLR, WebAssembly, CPython).

2. Система команд

В лекции 9 приведён пример инструкций f32a. Полный перечень — в документации wrench.

ИнструкцияЧто делает
+push(pop() + pop()) — снять два значения, сложить, положить результат
a!A = pop() — снять значение в регистр A (адресный)
@push(mem[A]) — прочитать память по адресу в A, положить на стек
!mem[A] = pop() — снять значение со стека и записать в память по адресу A
if Lif pop() == 0: PC = L — снять значение, если ноль, перейти на L
L (call)rpush(PC); PC = L — положить адрес возврата на стек возвратов, перейти на L
; (return)PC = rpop() — снять адрес возврата со стека возвратов
@+автоинкремент: косвенное чтение, затем указатель + 1 (из таблицы адресации лекции 8)

Режимы адресации

Из таблицы адресации лекции 8 для f32a указаны:

  • стековая — операнд на вершине стека (пример: +);
  • автоинкремент — косвенная адресация, затем указатель + 1 (пример: @+).

Прочие режимы адресации для f32a в таблице лекции 8 не указаны.

Классификация стековых машин

Из лекции 9 — по каким признакам различают стековые машины:

  1. Число стеков: один (S) или несколько (M) — обычно стек данных и стек возвратов.
  2. Размер стека: малый (S) — буфер на кристалле, единицы–десятки ячеек; большой (L) — в памяти.
  3. Число операндов инструкции: 0 — всё на стеке; 1–2 — можно явно указать ячейку памяти или смещение в стеке.

3. Требования к лабе

Из lab3-task.md — специфика именно для f32a:

  • использовать процедуры (требование ISA);
  • при использовании процедур — выработать схему именования меток, помогающую видеть структуру кода.

Общие требования (для всех ISA):

  • ввод через 0x80, вывод через 0x84;
  • 32-битное машинное слово по умолчанию;
  • ввод вне области определения — -1;
  • результат не помещается в слово — слово из байтов 0xCC;
  • код отформатирован, журнал не обрезан;
  • сдача одного задания — не чаще раза в 24 часа.

Почему процедуры для f32a — естественно: аргументы уже лежат на стеке данных, адрес возврата сам уходит на стек возвратов, сохранять регистры не нужно. В лекции 9 это показано сравнением: на стековой машине sum-of-squares — 5 «слов» Forth, а на risc-iv — 15 инструкций, из которых 8 — работа с кадром стека.

4. Пример кода

Из лекции 9 — процедуры на стековой машине (язык Forth; \ — комментарий, в скобках — состояние стека «до -- после»):

: square ( n -- n*n )     \ ": имя" -- определение
  dup * ;                 \ ";" -- конец и возврат

: sum-of-squares ( a b -- a*a+b*b )
  square swap square + ;  \ слово -- вызов

3 4 sum-of-squares        \ числа -- на стек; результат 25

Что происходит:

  • 3 4 — два числа кладутся на стек данных;
  • square — вызывается процедура: снимает вершину (4), кладёт 4*4=16; dup дублирует вершину, * перемножает две верхние ячейки;
  • swap меняет два верхних значения местами, чтобы второй square взял 3;
  • + складывает два квадрата.

Обрати внимание: в коде нет ни одного имени регистра — вся «передача данных» между операциями идёт через вершину стека. Это и есть главная идея архитектуры.

Ещё один пример из лекции 8 — линейная функция на стековой машине (стиль Forth):

A @ X @ *     \ stack, 0 operands
B @ + Y !     \ @ - read, ! - write

Читается как: положить A, положить X, перемножить, положить B, сложить, записать в Y. В таблице лекции у этого варианта 10 инструкций (больше всех), зато каждая — очень короткая.
