f32a

Стековая архитектура

1. Что это

Стековая машина — процессор, у которого операнды инструкций неявные: они берутся с вершины стека, результат кладётся туда же, а в инструкции кодируется только операция. Нет полей регистров — поэтому код получается очень компактным.

Ключевые термины:

  • Стек — структура «последним пришёл — первым вышел» (LIFO). push кладёт значение на вершину, pop снимает.
  • Операнд — то, над чем выполняется операция. У стековой машины операнды — это верхние ячейки стека.
  • Стек данных и стек возвратов — в f32a их два. На стеке данных лежат значения, на стеке возвратов — адреса возврата из процедур.
  • Регистры A и B — два вспомогательных регистра для адресов: @ читает по адресу в A, ! пишет по адресу в A. Это единственный способ добраться до памяти, кроме @p/!p с абсолютным адресом.

По классификации лекции 8 стековая архитектура — самая высокая плотность кода: операция занимает байт, полей регистров нет. Доступ к памяти — только через @ (чтение слова) и ! (запись слова). Примеры: f32a, JVM, WebAssembly.

Историческая справка из лекции 9: прообраз f32a — процессор F18A (Forth-процессор), на его основе сделаны матрицы GreenArrays GA144. Стековые машины применяют во встраиваемых и космических системах (Harris RTX 2010) и в виртуальных машинах (JVM, .NET CLR, WebAssembly, CPython).

2. Система команд

Комментарии в f32a — \, не ;. Символ ; — это инструкция Return, а не начало комментария. Это важно: код на acc32 с ;-комментариями в f32a не соберётся.

Арифметика и логика

Чего нет в f32a:

  • or нет. Побитовое ИЛИ собирается через Де Моргана: inv + and + inv = ~( ~a & ~b ).
  • swap нет. Поменять два верхних значения — через return stack (>r, >r, r>, r>) или через промежуточную ячейку памяти.
  • Сдвига на k бит нет. Только 2*/2/ на 1 бит, поэтому сдвиг на k — цикл из k итераций.

Классификация стековых машин

Из лекции 9 — по каким признакам различают стековые машины:

  1. Число стеков: один (S) или несколько (M) — обычно стек данных и стек возвратов.
  2. Размер стека: малый (S) — буфер на кристалле, единицы–десятки ячеек; большой (L) — в памяти.
  3. Число операндов инструкции: 0 — всё на стеке; 1–2 — можно явно указать ячейку памяти или смещение в стеке.

3. Требования к лабе

Из lab3-task.md — специфика именно для f32a:

  • использовать процедуры (требование ISA);
  • при использовании процедур — выработать схему именования меток, помогающую видеть структуру кода.

Общие требования (для всех ISA):

  • ввод через 0x80, вывод через 0x84;
  • 32-битное машинное слово по умолчанию;
  • ввод вне области определения — -1;
  • результат не помещается в слово — слово из байтов 0xCC;
  • .org 0x88 — данные начинаются сразу за MMIO-портами. Иначе данные начнутся с 0x100 и зря сожгут 120 байт, и код может не влезть в лимит памяти;
  • код отформатирован (wrench-fmt), журнал не обрезан;
  • сдача одного задания — не чаще раза в 24 часа.

Почему процедуры для f32a — естественно: аргументы уже лежат на стеке данных, адрес возврата сам уходит на стек возвратов, сохранять регистры не нужно. В лекции 9 это показано сравнением: на стековой машине sum-of-squares — 5 «слов» Forth, а на risc-iv — 15 инструкций, из которых 8 — работа с кадром стека.

4. Пример кода

Из лекции 9 — процедуры на стековой машине (язык Forth; \ — комментарий, в скобках — состояние стека «до -- после»):

: square ( n -- n*n )     \ ": имя" -- определение
  dup * ;                 \ ";" -- конец и возврат

: sum-of-squares ( a b -- a*a+b*b )
  square swap square + ;  \ слово -- вызов

3 4 sum-of-squares        \ числа -- на стек; результат 25

Что происходит:

  • 3 4 — два числа кладутся на стек данных;
  • square — вызывается процедура: снимает вершину (4), кладёт 4*4=16; dup дублирует вершину, * перемножает две верхние ячейки;
  • swap меняет два верхних значения местами, чтобы второй square взял 3;
  • + складывает два квадрата.

Обрати внимание: в коде нет ни одного имени регистра — вся «передача данных» между операциями идёт через вершину стека. Это и есть главная идея архитектуры.

Учебный код на f32a из wrench — чтение MMIO и запись результата (идиома @p addr a! @):

    .data
    .org 0x88
input_addr:     .word 0x80
output_addr:    .word 0x84
    .text
_start:
    @p input_addr a! @       \ прочитать слово из порта 0x80
    little_to_big_endian     \ вызов процедуры: T <- be(n)
    @p output_addr a! !      \ записать слово в порт 0x84
    halt

Как это читается:

  • @p input_addr — положить на стек значение ячейки input_addr (= 0x80);
  • a! — снять его в регистр A;
  • @ — прочитать слово (4 байта) из порта [A] = 0x80 — это вход;
  • little_to_big_endian — вызов процедуры (голое имя метки = Call, не Jump);
  • @p output_addr a! ! — то же в обратную сторону: адрес 0x84 в A, значение со стека в [A].

5. Грабли (из личного опыта)

  1. \, а не ;. ; — это Return. Код, скопированный из acc32, не соберётся.
  2. @ и ! — word, не byte. Чтение из MMIO 0x80 даёт сразу 32-битное слово, не байт. В brief и на слайде размер не указан — смотреть docs/f32a.md: @ ( -- value: i32 ).
  3. MMIO queue в conf wrench — список СЛОВ, не байтов. 0x80: [305419896] = одно слово 0x12345678; 0x80: [0x78, 0x56, 0x34, 0x12] = четыре отдельных слова (первое = 120).
  4. or нет. Через inv, and, inv.
  5. swap нет. Через return stack или промежуточную ячейку.
  6. <label> ; — это Jump, не «call + return». Голое <label> — Call. ; отдельно — Return.
  7. next использует return stack, не data stack. Счётчик кладётся через >r; для 32 итераций исходное значение = 31.
  8. if прыгает если TOS == 0 (как JZ), а не «если true». -if — если TOS >= 0.
  9. Код может не влезть в дефолтные 512 байт. .org 0x88 и memory_size: 0x1000 в conf решают. Но встроенные тесты wrench могут дать ровно 512 — надо влезать.
  10. dup не сбрасывает carry — это не баг, это для eam.
